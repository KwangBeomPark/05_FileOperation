# FileOps Hub 공통 정비 2단계 검수

검수일: 2026-10-07. 버전 1.4.3, 설치 AppId, 기존 설치 폴더와 `UserSetting` 보존 정책은 유지했습니다.

## 변경 결과

- 기존 배포 스테이징·서명·별칭·보존 반영 절차를 유지했습니다. 공식 `release/`의 접근 거부도 그대로이며 권한을 바꾸지 않았습니다.
- 구형 EXE를 새 파일 복사 전 `[InstallDelete]`로 삭제하던 규칙을 제거했습니다. 기존 바로가기 정리는 유지합니다.
- 삭제 후보와 종료 확인 대상은 기존 중앙 `APP_EXE_NAMES`에서 받습니다. `PrepareToInstall`에서 기존 uninstall AppId 등록·설치 위치·파일 해시를 먼저 기록합니다.
- Restart Manager 정상 종료 요청 뒤 첫 EXE 복사 전 `BeforeInstall`에서 현재·구형 EXE의 교체 가능 여부를 확인합니다. 사용 중이거나 접근이 거부되면 설치를 차단하며 강제 종료하지 않습니다. 트레이에 숨긴 경우에는 앱의 종료 메뉴로 실제 프로세스를 종료해야 합니다.
- `RestartApplications=no`로 이전 실행 상태를 자동 재시작하지 않습니다. 설치 후 실행은 새 `App05_FileOps.exe`입니다.
- 설치 성공 `ssDone`과 새 EXE SHA-256 일치, 사전 소유권·구형 해시 일치를 모두 만족할 때만 구형 EXE leaf를 정리합니다. 현재 EXE, 변경된 파일, 폴더·설정·로그·이력은 정리 대상이 아닙니다.

## 검증과 한계

- 전체 회귀 **230개 통과**. 새 검사는 실제 `installer_command()`와 중앙 식별자·호환 목록·바로가기 생성 결과로 격리 설치 정의를 컴파일합니다. 기존 구형 EXE 선제 삭제 검사를 새 보존 계약으로 갱신했습니다.
- 공식 `run_static_checks()`를 통해 사용자 자료 경로를 임시 폴더로 격리한 회귀, compileall, pip check, Ruff `E9,F,B`를 통과했습니다. 초기 직접 회귀 호출에서는 기존 로거가 실제 앱 로그 위치에 진단 기록을 추가했으며 해당 로그를 임의 삭제하지 않았습니다. 사용자 설정·업무 데이터는 수정하지 않았습니다.
- Inno Setup 6.7.3 컴파일 통과. 독립 검수의 AppId 전처리 assertion과 호환 목록 검사도 통과했습니다.
- Antigravity Gemini 3.8 Flash High/effort high의 제안을 검토하고 지원되지 않는 API·이벤트 순서·목록 오류를 수정했습니다. 별도 Codex 에이전트가 성공 후 삭제·소유권·해시 조건을 교차 검수했습니다.

실제 인증서 서명·설치·업그레이드·제거·게시를 실행하지 않았습니다. 작업·예약 실행 중 종료·거부, 실패·취소 후 구버전 실행, 사용자 지정 경로와 제거 후 자료 보존은 실제 Windows 검수 항목입니다. 접근이 거부된 기존 공식 배포물을 검증했다고 주장하지 않습니다.
