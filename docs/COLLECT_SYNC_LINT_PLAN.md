### 1단계 — 자동 수집 기능의 안전성부터 닫기

린트와 섞지 않고 결함별 재현 테스트를 먼저 추가한다.

- **수동 확인창과 예약의 경쟁**: `collect_sync_tab.py`의 `start_execution()`은 확인창을
  연 후 `_start()`에서 실행을 예약한다. 모달 창에서도 QTimer가 동작할 수 있으므로,
  확인창이 떠 있는 동안 수집/통합 예약과 다른 시작 경로가 끼어들지 않는지 재현한다.
  확인 중 가드를 추가한다면 예약 시도 횟수는 소비하지 않아야 한다.
  이는 정적 코드에서 확인한 미검증 경쟁 위험이며, 현재 재현 테스트는 없다.
- **대응 관계 저장 실패**: 파일 복사 성공 직후 `CollectState.save()`가 실패한 경우의
  결과·오류·재시도 동작을 실패 주입으로 확인한다. 파일과 JSON은 하나의 트랜잭션이 아니다.
  파일은 보존하되 성공으로 표시하지 않고 사용자가 안전하게 복구할 수 있어야 한다.
- **심볼릭 링크의 경계**: 엔트리 링크는 건너뛰지만 원본 루트 자체가 링크인 경우의
  계약도 검증한다. Windows junction은 지원 환경에서 별도 시험한다.
  이미 고지된 드라이브 문자/UNC 별칭 문제를 임의로 상태 마이그레이션하지 않는다.
- **시작 실패와 이력**: 네이티브 워커 시작 실패가 이전 예약 시작·종료 이력을
  불필요하게 지우지 않는지 확인한다. 정상 시작/시작 전 실패/실행 후 실패/취소를 구분한다.
- **종료/업데이트 경계**: 중지 요청 뒤 워커가 살아 있으면 창이나 인스톨러 실행을
  진행하지 않는다. 트레이 숨김은 예약을 멈추지 않아야 한다.
- 그룹 변경·저장 실패·동일 시각 다중 그룹·잠긴 파일·영문/폴란드어 오류 메시지와
  결과 표의 경로 식별성을 다시 확인한다. docs/task.md와 walkthrough.md는 끝에만 덧붙인다.

종료 기준: 관련 신규 테스트 + 전체 회귀 통과, 오류/취소가 성공으로 보이지 않음,
실행 확인 중 예약/실행 중복 없음. 필요한 수동 검증은 자동 검사와 별도 표시.

### 4단계 — 예외 처리와 외부 자원

- BLE001 99건, S110 17건을 모듈별로 분류한다.
- 순수 Python 입력 검증은 예상 예외를 명시한다.
- Qt 워커 최상위, Office COM, Windows DPAPI, 외부 프로세스 같은 경계는
  최종 안전망이 필요한지 검토한다. broad catch 자체를 없애 앱을 종료시키지 않는다.
- 필수 cleanup은 `finally`에 남긴다. cleanup 실패가 원래 오류를 가리지 않게 한다.
- 로그에는 진단을 남기되 암호·토큰·이메일 등 민감값을 추가하지 않는다.
- 합리적인 broad catch가 반드시 필요한 경우, 해당 한 줄에 이유를 쓴 좁은 noqa를 검토한다.
  전역 ignore, 파일 전체 ignore, 자동 `--add-noqa`는 허용하지 않는다.

종료 기준: 실패 주입/자원 해제/원본 보존/원자 저장 테스트 통과. native 미실행은 별도 명시.

### 5단계 — 시간 처리와 예약

- DTZ 39건을 예약 정책, 실행 이력, 파일 시각 표시, 테스트 fixture로 분류한다.

- 시간만 읽는 HH:mm 파서와 실제 시점을 저장하는 timestamp를 구분한다.
- 자정 경계, 재시작 당일 따라잡기, 같은 날 중복 금지, 시작 전 재시도,
  이전 naive 이력 읽기, DST/시각 변경을 검증한다.
- 저장 포맷 변경이나 UTC 마이그레이션이 필요하면 구현 전에 사용자에게 결정받는다.

종료 기준: 기존 예약 정책과 저장 이력 호환 유지, 관련 DTZ 진단은 의미 있는 코드 또는
근거 있는 좁은 예외로 해소, 전체 테스트 통과.
