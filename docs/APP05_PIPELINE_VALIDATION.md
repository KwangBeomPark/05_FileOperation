# App05 정규화·배포 파이프라인 검수 (2026-10-06)

## 판정

로컬 구현과 미서명 실제 빌드 검증을 완료했습니다. 새 서명 릴리즈의 완료 판정은 아닙니다.
공식 제품 ID/실행 파일은 App05_FileOps / App05_FileOps.exe, 표시명은 FileOps Hub입니다.
기존 Windows 설치/중복 실행 ID와 UserSetting은 유지합니다.
현재 소스 버전은 1.4.2이며 새 버전·커밋·서명·공개는 별도 결정이 필요합니다.

## 확인한 증거

- 회귀 테스트 229개 통과. 실제 빌드의 로그는 로컬 tools/_local/app05-build-final.log입니다.
- Ruff E9/F/B, compileall, pip check, 모든 PowerShell 스크립트 구문 검사 통과.
- 표준 build.ps1 -Unsigned -BuildLauncher로 실제 PyInstaller 앱/런처 및 Inno Setup 컴파일 성공.
  최종 개발 세트는 dist/packaging/v1.4.2-su5iginj입니다. 앱도 이 폴더에 격리되어 있습니다.
- 앱의 50개 코드 모듈 및 런처의 3개 코드 모듈을 현재 소스와 비교했습니다.
  번들 icon.ico/icon.png 바이트도 일치합니다. EXE를 실행하지 않는 검사입니다.
- 새 앱의 PE OriginalFilename/InternalName은 App05_FileOps.exe / App05_FileOps입니다.
  개발 EXE는 미서명이며 공개용으로 사용하지 않습니다.
- 기존 서명 설치 파일의 두 로컬 별칭은 원본 SHA-256 및 타임스탬프/게시자가 동일합니다.
  SignTool /pa /all /v, Authenticode Valid를 실제로 확인했습니다.
  PowerShell 7 → Python → 절대경로 Windows PowerShell 검사도 두 파일에서 통과했습니다.
- 미서명 공개 요청은 빌드 전에 실패합니다. 현재 v1.4.2의 다른 소스 커밋 재서명도 태그 검사로 차단합니다.
- GitHub의 기존 v1.4.2는 정식 공개 상태/기존 4개 자산을 유지합니다. 새 파일을 업로드하지 않았습니다.

## 정리 결과와 복구

정리 전 release는 44개 파일, 2,153,889,923바이트였습니다. 최신 파일의 해시·서명을 먼저
검증한 뒤 과거 파일 38개, 2,007,781,004바이트를 **영구 삭제**했습니다.
공개된 과거 파일은 GitHub에서 다시 받을 수 있으나 미공개 로컬 빌드는 복구하지 못할 수 있습니다.
설치된 앱·설정·로그·예약 이력·GitHub 이력은 삭제하지 않았습니다.

현재 release는 4개 파일, 270,077,417바이트(약 257.6MiB)입니다.
두 설치 파일은 **기존 공개 v1.4.2의 파일명 별칭**입니다. 내부 앱은 기존 공개본 그대로이고
메타데이터도 원본 product_id, alias_product_id, alias_only=true를 명확히 기록합니다.
재공개는 차단됩니다. 원본 최신 6개 파일은 tools/_local/published-v1.4.2-*에 보존했습니다.

## 독립 Opus 5.5 검수와 수정

로컬 Claude CLI 2.1.287에서 실제 모델 claude-opus-5-5 / firstParty를 확인했습니다.
Read/Glob/Grep만 허용하고 실행·수정·서명·설치·공개 권한과 사용자/프로젝트 훅은 비활성화했습니다.
1차 검수 결과는 tools/_local/opus55-review.json에 보관합니다. 오류·권한 거부는 없었습니다.

| 발견 사항 | 처리 |
| --- | --- |
| 새 버전도 기존 체크섬/메타데이터 때문에 마지막 promotion에서 실패 | 수정. 버전별 EXE만 덮어쓰기 차단하고 메타데이터는 이전 세트와 함께 백업·교체. 회귀 테스트 추가 |
| 사용자 지정 설치 업그레이드가 다른 폴더로 설치되어 설정을 못 읽음 | 수정. UsePreviousAppDir=yes, 신규 설치 기본 경로는 그대로. 실제 PC 업그레이드 검수는 별도 |
| 기존 v1.4.2 클라이언트는 새 듀얼 파일명을 모름 | 구형 소스로 확인. 기존 UI의 릴리즈 페이지 버튼을 통한 한 번의 수동 업그레이드를 문서화. 구형 명칭 배포물을 재도입하지 않음 |
| PowerShell 7 모듈 상속/PATH 검색이 신뢰 검사에 영향 | 수정. 시스템 절대경로·PSModulePath 제거·기본 모듈 명시·Console 출력. 실제 검증 통과 |
| 개발 앱이 dist의 서명 앱을 덮어씀 | 수정. 미서명 앱도 고유 staging에 격리 |
| 다른 커밋으로 공개된 버전의 재서명 가능 | 수정. 서명 전에 버전 태그와 현재 소스 커밋 검사 |
| 보호 파일 기록에 staging 경로가 있어 청소 검증 누락 | 수정. 배포 EXE 기록은 최종 release/name 경로 사용 |
| 옛 EXE/환경변수명/누락한 서명 도구 처리 | 중앙 호환 목록 및 설치 폴더의 leaf-only 정리. 누락한 명시 도구는 실패. 공개는 인증서 명시 선택 필요 |

수정 후 실제 Opus 5.5 독립 재검수도 완료했습니다. tools/_local/opus55-recheck.json의
canonicalModel은 claude-opus-5-5이며 오류·권한 거부가 없습니다. 기존 P1/P2는 수정·완화 또는
명시적 잔여 위험으로 분류됐고 **현재 코드에서 남은 배포 차단 오류는 발견하지 못했다**는 판정입니다.
이는 실제 개인키 서명·설치 성공 인증이 아닙니다. 재검수 후에도 229개 회귀 테스트와 정적 검사를
재실행해 통과했고, 최종 실제 개발 빌드의 소스/아이콘도 다시 비교했습니다.

## 유지할 방어와 다음 개선

전체 파일 집합·중복/잘못된 체크섬·메타데이터 해시·두 설치 파일 동일성·실제 Windows 신뢰를
검증합니다. 실패 시 이전 release를 보존하고 promotion 실패는 복원합니다. 공개는 명시적
-Publish만 허용하며 깨끗한 main/허용된 origin/일치하는 커밋을 요구합니다. Draft 업로드의
서버 크기와 digest를 검사하고 나서 공개합니다. 이미 공개된 버전은 덮어쓰지 않습니다.

업로드 실패 시 태그/Draft가 남을 수 있으므로 수동 복구를 명시합니다. 자동 삭제/덮어쓰기는
하지 않습니다. 현재 gh의 assets digest 제공 여부는 실제 공개본 조회로 확인했습니다.
다음 개선 후보는 다음과 같습니다. 이번 작업에는 자동 삭제나 별도 배포 방식 변경을 추가하지 않았습니다.

- 개발 staging/이전 배포 백업의 보관 개수·기간 정책.
- 다음 서명 빌드 실패가 이전 미공개 세트의 dist 앱 검증에 영향을 주지 않도록 서명 앱 스냅샷 보관.
  현재는 release 설치 파일 자체는 보존되며 검증이 불일치하면 안전하게 실패합니다.
- 공개 직전 현재 Latest보다 높은 버전인지 확인하는 추가 방어.
- 패키지에 들어 있는 코드 비교뿐 아니라 필수 모듈의 누락 검증/실제 시작 테스트 확대.

경로 업그레이드·바로가기/작업표시줄/트레이 렌더링·자동 시작·제거 및 Office 실작업은 미검증입니다.
기존 인증서나 서명 파일을 확인한 것을 새 코드 서명 성공으로 표현하지 않습니다.
